# QuantAgent MCP tools

Generated by `scripts/gen_tools_doc.py` from the running server and the current database
(data_nature **real**, data as of 2026-10-19, version 1). Example funds are picked automatically (longest NAV histories). Errors,
including a benchmark tool call without TRI data loaded, are shown as returned.

## Running

```bash
pip install -e .[dev]
quantagent setup                          # download AMFI data, ingest -> data/db/quantagent.db
npx @modelcontextprotocol/inspector quantagent-server   # browse and call the tools
quantagent-server --transport streamable-http --port 8000
docker build -t quantagent . && docker run -i --rm -v qa:/app/var quantagent serve
```

Claude Desktop (`claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "quantagent": {
      "command": "C:/path/to/quantagent/.venv/Scripts/quantagent-server.exe",
      "env": {
        "QUANTAGENT_DB_URL": "sqlite:///C:/path/to/quantagent/data/db/quantagent.db",
        "QUANTAGENT_MODEL_DIR": "C:/path/to/quantagent/models/registry"
      }
    }
  }
}
```

## Conventions

* Returns, volatility, drawdowns and rates are fractions (`0.12` = 12%); expense ratios are percent.
* Every result has `meta` (period, n_obs, data_as_of, data_version, calc_version, data_nature,
  assumptions, request_id), `warnings` and `excluded`.
* Failures return `is_error: true` with JSON `{code, message, details}`. Codes: `INVALID_INPUT`,
  `NOT_FOUND`, `INSUFFICIENT_HISTORY`, `NO_OVERLAP`, `DATA_QUALITY`, `MODEL_UNAVAILABLE`, `INTERNAL`
  (INTERNAL details carry a
  `request_id` that matches the server's stderr log).
* Unknown argument names are rejected. No argument accepts SQL, column names or expressions.

## `search_funds`

Find mutual fund schemes and their codes by name, category, fund house, plan or option.

Use this first, to get the 6-digit scheme_code that every other tool needs.
Do NOT use it to compare or rank performance: use rank_funds (screening) or compare_funds.
At least one of query, category, fund_house, plan_type, option_type is required. Matching is
case-insensitive substring matching. Results are paginated with limit/offset.

| Argument | Type | Default | Notes |
|---|---|---|---|
| `query` | string | null | Text in the scheme name or code, e.g. 'bluechip'. pattern=^[A-Za-z0-9 &.,()/+-]+$; minLength=1; maxLength=100 |
| `category` | string | null | Category or sub-category text, e.g. 'Large Cap'. pattern=^[A-Za-z0-9 &.,()/+-]+$; minLength=1; maxLength=100 |
| `fund_house` | string | null | Fund house text, e.g. 'HDFC'. pattern=^[A-Za-z0-9 &.,()/+-]+$; minLength=1; maxLength=100 |
| `plan_type` | enum: Direct, Regular | null |   |
| `option_type` | enum: Growth, IDCW, NA | null |   |
| `status` | enum: active, closed, merged, any | "active" |   |
| `limit` | integer | 20 |  minimum=1; maximum=50 |
| `offset` | integer | 0 |  minimum=0; maximum=100000 |

Example call:

```json
{"query": "BANDHAN", "limit": 3}
```

## `get_nav_history`

Return the NAV time series of one scheme, optionally resampled to weekly or monthly.

Use for charts or to inspect raw prices. Do NOT use to compute returns or risk yourself:
get_risk_metrics, get_benchmark_comparison and compare_funds do that with documented methods.
Without dates, the full history is returned. If more than max_points points exist, the most
recent max_points are returned and truncated=true. Daily output also reports trading days
with no NAV (gaps) on the trading calendar.

| Argument | Type | Default | Notes |
|---|---|---|---|
| `scheme_code` | string | required | 6-digit AMFI scheme code, e.g. '119551'. pattern=^\d{6}$ |
| `start_date` | string | null | Inclusive start date (YYYY-MM-DD). Use instead of period. format=date |
| `end_date` | string | null | Inclusive end date (YYYY-MM-DD). Defaults to the latest data date. format=date |
| `frequency` | enum: daily, weekly, monthly | "daily" |   |
| `max_points` | integer | 2000 |  minimum=1; maximum=5000 |

Example call:

```json
{"scheme_code": "118479", "frequency": "monthly", "start_date": "2026-04-19"}
```

## `compare_funds`

Compare 2-10 schemes side by side on the SAME dates.

Returns per fund: total return, CAGR, volatility, Sharpe, Sortino, maximum drawdown, n_obs;
plus the shared period, a daily-return correlation matrix and fair_comparison with reasons
(mismatched windows, IDCW plans, Direct mixed with Regular, different sub-categories, short
history). Use when the user names specific funds. Do NOT use to search a whole category for
the best funds (use rank_funds) or for benchmark-relative stats (get_benchmark_comparison).

| Argument | Type | Default | Notes |
|---|---|---|---|
| `scheme_codes` | array[string] | required | 2-10 distinct scheme codes. minItems=2; maxItems=10 |
| `period` | enum: 1y, 3y, 5y, max | null | Trailing window; default 3y. Use instead of dates.  |
| `start_date` | string | null | Inclusive start date (YYYY-MM-DD). Use instead of period. format=date |
| `end_date` | string | null | Inclusive end date (YYYY-MM-DD). Defaults to the latest data date. format=date |

```json
{"scheme_codes": ["118479", "119598", "103490"], "period": "3y"}
```

## `rank_funds`

Screen and rank many funds by one metric or a weighted composite over a 1y/3y/5y window.

Use for "best/top/worst funds in a category" questions. Do NOT use for one fund's details
(get_risk_metrics) or for a handful of named funds (compare_funds). Funds lacking history or
the metric are listed in `excluded` with the reason. dedupe='direct_growth' keeps one plan per
scheme so Direct and Regular versions of the same fund don't both appear.

| Argument | Type | Default | Notes |
|---|---|---|---|
| `metric` | enum: total_return, cagr, volatility, sharpe, sortino, max_drawdown, alpha, expense_ratio | null | Rank by one metric. Give metric OR weights.  |
| `weights` | object | null | Composite score, e.g. {'sharpe': 2, 'max_drawdown': 1}.  |
| `period` | enum: 1y, 3y, 5y | "1y" |   |
| `category` | string | null | Category or sub-category text. pattern=^[A-Za-z0-9 &.,()/+-]+$; minLength=1; maxLength=100 |
| `fund_house` | string | null | Fund house text. pattern=^[A-Za-z0-9 &.,()/+-]+$; minLength=1; maxLength=100 |
| `max_expense_ratio` | number | null | In percent, e.g. 1.0. minimum=0; maximum=5 |
| `dedupe` | enum: direct_growth, none | "direct_growth" |   |
| `top_n` | integer | 10 |  minimum=1; maximum=50 |
| `ascending` | boolean | null | Override the metric's natural sort order.  |

Example call:

```json
{"metric": "sharpe", "period": "3y", "category": "Large Cap", "top_n": 3}
```

## `get_risk_metrics`

Risk profile of ONE scheme: volatility, Sharpe, Sortino, alpha, beta, R^2 and maximum drawdown.

Use for a single fund's risk. Do NOT use to screen many funds (use rank_funds) or to compare
a few funds side by side (use compare_funds). For excess return, tracking error and capture
ratios against the benchmark use get_benchmark_comparison.
Rules: 1y/3y/5y windows need NAVs on >= 90% of trading days; volatility, Sharpe and Sortino
need >= 60 returns; alpha/beta need >= 120 returns shared with the benchmark.

| Argument | Type | Default | Notes |
|---|---|---|---|
| `scheme_code` | string | required | 6-digit AMFI scheme code, e.g. '119551'. pattern=^\d{6}$ |
| `period` | enum: 1y, 3y, 5y, max | null | Trailing window; default 3y. Use instead of dates.  |
| `start_date` | string | null | Inclusive start date (YYYY-MM-DD). Use instead of period. format=date |
| `end_date` | string | null | Inclusive end date (YYYY-MM-DD). Defaults to the latest data date. format=date |
| `benchmark` | string | null | Override the scheme's benchmark for alpha/beta. pattern=^[A-Za-z0-9_]{1,40}$ |
| `risk_free_annual` | number | null | Annual risk-free rate, e.g. 0.065. minimum=0; maximum=0.2 |

## `get_benchmark_comparison`

Compare ONE scheme with its benchmark over the same dates.

Returns fund vs benchmark CAGR, volatility and drawdown, plus excess CAGR, tracking error,
information ratio, beta, alpha, R^2 and monthly up/down capture. Use to answer "did this fund
beat its index?". Do NOT use to compare funds with each other (compare_funds) or for a fund's
standalone risk (get_risk_metrics). Needs >= 120 shared daily returns.

| Argument | Type | Default | Notes |
|---|---|---|---|
| `scheme_code` | string | required | 6-digit AMFI scheme code, e.g. '119551'. pattern=^\d{6}$ |
| `benchmark` | string | null | Benchmark series; defaults to the scheme's own benchmark. pattern=^[A-Za-z0-9_]{1,40}$ |
| `period` | enum: 1y, 3y, 5y, max | null | Trailing window; default 3y. Use instead of dates.  |
| `start_date` | string | null | Inclusive start date (YYYY-MM-DD). Use instead of period. format=date |
| `end_date` | string | null | Inclusive end date (YYYY-MM-DD). Defaults to the latest data date. format=date |

Example call:

```json
{"scheme_code": "118479", "period": "3y"}
```

Error returned:

```json
{
 "code": "NOT_FOUND",
 "message": "Scheme 118479 has no benchmark series; pass benchmark explicitly.",
 "details": {
  "available": []
 }
}
```

## `check_data_quality`

Check NAV data quality per scheme and report ok / warn / fail with examples.

Use before trusting any metric for a scheme, or to audit the dataset. Do NOT use for
performance figures. fail checks: duplicate_dates, nonpositive_nav, future_dates.
warn checks: calendar_gaps (trading days with no NAV), extreme_moves (|daily return| > 15%),
stale_runs (same NAV 5+ days), missing_metadata, idcw_option (not a total-return series).
Runs the same code that ingestion uses. Results are paginated with limit/offset.

| Argument | Type | Default | Notes |
|---|---|---|---|

## `predict_volatility`

Forecast a scheme's annualised volatility over the next 21 trading days.

Use when asked how volatile a fund is likely to be next month, or for a forward-looking risk
estimate. The model is a log-volatility regression on realised-volatility features (HAR-RV
style), selected by walk-forward evaluation against naive, EWMA, HAR-RV and GARCH baselines;
its out-of-sample scores are returned in `model`. Do NOT use for historical volatility; use
get_risk_metrics. Fails with MODEL_UNAVAILABLE if no model has been trained (scripts/train_vol.py).

| Argument | Type | Default | Notes |
|---|---|---|---|
| `scheme_code` | string | required | 6-digit AMFI scheme code, e.g. '119551'. pattern=^\d{6}$ |
| `as_of` | string | null | Forecast origin (YYYY-MM-DD); default the latest NAV date. Only NAVs up to this date are used. format=date |
